# Контроль кассовой дисциплины — веб-интерфейс

Next.js-фронтенд для сервиса из `../service`. Экран отчёта повторяет макет `../design/report/`.

- `/` — загрузка видео (прогресс отправки).
- `/jobs/[id]` — ожидание анализа и отчёт: плеер с маркерами нарушений, таймлайн по типам,
  карточки с кадрами-доказательствами, уверенностью и нормами НБРК, отметки «Подтвердить / Не нарушение»
  (хранятся в localStorage), выгрузка JSON вместе с отметками.

Браузер обращается только к Next-серверу: `/ui/*` и `/api/v1/*` проксируются на бэкенд
(`next.config.ts`), поэтому CORS не нужен. Видео на сервере не хранится, плеер играет локальный файл;
после перезагрузки страницы файл можно выбрать заново.

## Запуск

Нужен [bun](https://bun.sh) (Node.js не обязателен) и запущенный сервис на `:8000`.

```bash
bun install
bun run dev            # http://localhost:3000
```

Другой адрес бэкенда — через `BACKEND_URL`. Правила прокси фиксируются при сборке,
поэтому переменная нужна и на `build`:

```bash
BACKEND_URL=http://127.0.0.1:8000 bun run build
bun run start
```

Docker (адрес бэкенда задаётся при сборке):

```bash
docker build --build-arg BACKEND_URL=http://kassa:8000 -t kassa-frontend .
docker run -p 3000:3000 kassa-frontend
```

Проверки: `bun run lint`, `bun run typecheck`.
